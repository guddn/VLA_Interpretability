## 1. 주제 탐색 (2026-08-18 ~ 08-20)

### 08-18 · VLA 의 LLM 백본 비판 — `claude/vla-llm-backbone-비판-선행연구-정리.md`
- **출발 아이디어**: "LLM 은 물리 상호작용에 부적합하다 → CNN 처럼 bias 있는 구조 / 실세계 데이터 파이프라인 재구성"
- **판정**: 문제의식은 타당하나 novelty 없음. VLM4VLA(2601.03309)는 word embedding 을 얼려도 거의 무해하고 **vision encoder** 가 병목이라 보고,
  Compression Gap(2604.03191)은 **이산 action token** 을 병목으로 지목. 기하 bias(G3VLA), 대칭 bias(EquiDiff), 비-LLM world model(V-JEPA 2-AC)이 이미 선점
- **반복 패턴 지적**: 이전의 "중간 hidden state 를 action 표현으로" 아이디어와 같이 **"큰 구조를 바꾸겠다"** 는 프레임이 학부 스케일에서 막힘
- **남긴 씨앗**: "진단 연구 (가장 추천) — VLA 는 언어 백본을 실제로 쓰는가를 mechanistic 하게 측정" + IGAR(2603.06001) 존재 확인 ← **현재 프로젝트의 출발점**

### 08-18 · VLA interpretability 선행연구 지도 — `claude/vla-interpretability-선행연구-및-연구방향.md`
- 방법론 11계열(probing, 인과 개입, SAE, steering, 통합 진단, 벤치마크, 표현 품질, token pruning, 실패 예측, faithfulness, 고전)로 정리
- 읽힌 구조: **분야가 "관찰 → 개입"으로 이동** (ISS, knockout, patching), "성공률이 차이를 가린다", LIBERO 는 성능 벤치마크로는 포화지만 **통제 환경으로 적합**
- 실행 메모: **OpenVLA-7B 로 시작** (autoregressive 라 KL·patching 이 깔끔) ← 이후 그대로 채택

### 08-18 · RL / world model 선행연구 — `claude/vla-rl-world-model-선행연구-정리.md`
- "RL 처럼 스스로 물리를 배우는 VLA" 검토 → RL(보상 최적화) ≠ 물리 이해(예측 학습). RL 계열은 전부 VLM 백본 위에 얹는 **보완재**, SFT 0% 에서는 RL 불가
- 정정: 앞 문서의 "힘/촉각 modality 는 빈 곳"은 **틀림** (2026년 기준 두꺼운 연구군)

### 08-18 ~ 08-20 · World model 트랙 (병행 검토, 현재는 보류)
- `world-model-연구동향-2026.md` (08-18): 성능 경쟁은 산업 랩, 학술적으로 열린 곳은 "진짜 물리를 아는가" 평가·진단
- `world-model-물리이해-검증-연구방향.md` (08-18): 후보 A "물리 파라미터가 **표현되는가 vs 쓰이는가**" — activation patching 으로. Dreamer 4 과대평가 교정
- `world-model-물리평가-2026하반기-업데이트.md` (08-19): 1차 근거를 WorldBench → GAUGE(2608.05948)로 교체 권고 ("형태는 맞고 값이 틀린다")
- `world-model-물리표현-판정방법론.md` (08-19): 증거 사다리 L0–L5 (관측가능성 → 디코딩 → 분리성 → 인과 → **규칙성** → 필요성), "steering 단독으로는 부적합"
- `wam-계보-필독논문.md` (08-20): WAM 정의·계보·독서 순서 (내용이 같은 중복본 `world-model-physical-ai-계보-정리.md` 는 10-14 삭제)

## 3. 환경 구축과 구조 검증 (~2026-09-22)

- **환경 문제 연쇄 해결**: GPU 번호 체계 불일치(`CUDA_DEVICE_ORDER=PCI_BUS_ID`), EGL 번호 ≠ CUDA 번호, 메시지 없는 AssertionError(mujoco 3.x → **2.3.0** 고정),
  numpy 2.x 충돌(`PIP_CONSTRAINT`), 드라이버(cu118), `pick` 이 L 에서 빠지는 offset 앞 공백 버그, 291 vs 290 길이 에러(29871 토큰)
- **구조 검증(01) 통과**: 32층·32헤드, visual span `[1, 257)` = 256, L 태깅 육안 검증, eager attention 반환
- **모델 입력 확인(07, 09-22)**: `pixel_values` 6채널(DINOv2 + SigLIP), 224×224, 렌더 이미지와 구도 상관 0.9985
- **단일 스텝 관측 (09-22)**: R_raw 0.386 (균등 기준 0.0725 의 5.3배), R_norm 0.81, BOS(sink) 질량 0.434 →

## 5. 분석 경로 버그 두 개 (발견 09-30 → 수정 10-06)

- **Q 행 ↔ logit 행 한 칸 어긋남**: attention·knockout 은 action 토큰 자기 자리, KL 은 예측 자리 → DoF 0 의 KL 이 항상 0 이었음 → **Q = A − 1 로 통일**

## 7. 이미지 개입 · 치환 · 연구 방향 재정의 (2026-10-14)

### 7-1. 06 이미지 개입
- other_scene KL 11.69 (04 swapped 보다 큰 장면 28/30, 중앙 2.4배), hflip 5.69, patch_shuffle 9.61, noise 10.13
- noise·patch_shuffle 에서 R_raw 0.39 → 0.53. "Text 를 더 본다 → 언어 무시 주장에 반론" 해석은 **빈틈 2개**: Vision 질량 감소일 수도 있음 / 본다 ≠ 쓴다
  → 검정 가능한 형태 "이미지가 망가지면 KL_L 이 커지는가(보상 가설)" 로 재정의 (미실행)

### 7-2. 출력 구조 정리와 명명 규칙
- `outputs/<NN_스크립트명>/` 구조로 정리, `vlamod/paths.py` 도입. **"Stage" 표기 폐지, 스크립트 번호로만**

### 7-3. 09 임베딩 치환 — knockout 의 약점 발견
- 설계 중 발견: 02 의 knockout 은 Q 행만 막아 **직접 효과**만 잼 (우회 경로 L 쪽 4개, V 쪽 33개)
- 0층 평균 치환(총 효과)을 같은 프레임에서 비교: 치환/knockout 비 **V 1.58 > L 1.17** → knockout 은 이미지 의존을 과소평가
- **H2 부호 반전**: R_raw ↔ causal_ratio 가 knockout +0.35 / 치환 −0.17. 두 방법 모두에서 버티는 것은 R_raw ↔ KL_L(+0.30~+0.42)뿐
- 사용자 질문 "그냥 완전 차단을 쓰면 되지 않나" → 총 효과를 주 지표로 하되, 결과를 보고 지표를 고르면 순환이 됨 / 완전 knockout 제안

### 7-4. 목표 재확인과 방향 재정의
- 사용자 목표 정리: **"Attention 분포 등으로 Vision 편향을 직접 확인하고, 그 원인과 분포를 찾는다"**
- 지금까지 데이터의 요약: 지시문이 **있어야** 작동하지만, **무엇을 할지**는 이미지 내용으로 더 많이 정함 (내용 수준 편향)
- **원인 가설 H3**: 배치 → 과제 1:1 이라는 **데이터 지름길**. bddl 확인 중 **task 7 / 9 (배치 동일, 목표만 반대)** 발견 → 구조 vs 데이터 판별 실험
- 합의한 방향: **행동 편향 → 내부 지표 → 원인(구조 vs 데이터) → 원인에 맞는 개선**, 단계마다 관문
- 프로젝트 문서 `claude/vla-연구방향-2026-10.md`, `claude/vla-실험현황-스크립트별.md` 작성 (구 현황 문서 대체)
- 저장소 `docs/00–06`, README 를 스크립트 번호 기준으로 전면 개정

### 7-5. 10 ICBench 방식 모순 지시 — task 0 파일럿
- IGAR 논문 전문 확인: ICBench 지시문 **미공개** → V1–V4 분류를 따라 직접 생성 + 우리 추가 V5(그릇 없는 위치) · R(방해 그릇 위치 = 실행 가능한 다른 명령)

| 변형 | 바뀐 것 | 가짜 성공 (정상 성공 init 9개 중) |
|---|---|---|
| V1 / V2 / V3 | 색 (blue, green) | 9 / 8 / 8 |
| V4 | 관계 (under) | 9 |
| **V5** | 위치구 (on the stove) | **0** — 8번은 아무 그릇도 안 듦 |
| **R** | 위치구 (next to the ramekin) | **2** — 2번은 방해 그릇을 올림, 나머지는 멈춤·실패 |

- **해석**: 속성·관계 단어는 무시(IGAR 의 OFT 결과 재현), **위치구는 따름**. 유력한 설명 — spatial 학습 지시문은 위치구만 다르고 나머지 단어는 항상 같음 →
  **학습 중 변하지 않은 단어는 읽도록 학습되지 않음** (04 paraphrase 의 작은 KL 과도 일치). 내부에서는 아직 미검증
- **다음 방향 (사용자 결정)**: V1–V4 로 행동 수준 편향 확인 → **여러 개입으로 "어디가 문제인지" 좁힌다**. 11 의 질문:
  "blue 는 무시, stove 는 따름 — (a) 안 보는가 (b) 보지만 구분 못 하는가 (c) 구분은 되는데 행동으로 안 이어지는가"
